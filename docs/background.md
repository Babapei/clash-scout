# 背景与设计

## 最初的问题：在学校用不了

家里正常，一到学校代理就连不上。

排查下来是两件事叠加：

| 问题 | 说明 |
|---|---|
| **校园网封了节点 IP** | 一部分 IP 在学校直接不通，换到家里或手机热点就好了 |
| **机场自己也有一批死 IP** | 在哪儿都不通，跟校园网无关 |

同一个域名每次解析出来的 IP 不一样，所以表现出来就是「时好时坏」。

- **校园网这边**：常见手段是 IP 黑名单、端口限制、DPI 识别或 QoS 限速；很多是设备默认策略，不是管理员专门针对你
- **机场这边**：多 A 记录轮询 + 定期换 IP，本来是为了冗余，但也意味着池子里混着死 IP

**光靠感觉分不清是哪一种**——这就是做这个工具的原因。

## 它做什么

| 能做的 | 说明 |
|---|---|
| **记录** | 按网络环境（家 / 学校 / 热点）记下每个 IP 的状态 |
| **对比** | 同一批 IP 在不同网络下的表现，一眼看出是谁封的 |
| **推荐** | 告诉你当前该用哪个 IP |

Clash 自己不会告诉你这些：它不存历史，也不告诉你「现在连的是好 IP 还是坏 IP」。

## 想达成什么

**目标：不管哪个网络封了多少 IP，都能快速找到还能用的，并把它固定下来。**

| 阶段 | 内容 | 状态 |
|---|---|---|
| **第一步** | 记录 + 找出能用的 | ✅ 已做 |
| **第二步** | 一键固定到 Verge | 🚧 手动能做，自动化待补 |
| **第三步** | IP 失效时自动换下一个 | 📋 规划中 |

## 已经确认的

- 同一个 IP 在**不同网络**下结果可能完全相反（家通 / 校不通）
- 因此有三类 IP：**健康** / **被某个网络封** / **机场死 IP**
- DNS 返回的 IP 秒级变化，但**单个 IP 的存活是分钟到小时级**
- 不同**端口**的可用性可能完全不同
- Verge 不保存历史，也不会告诉你「现在连的是好 IP 还是坏 IP」

## 当前边界

这些是「还没做」，不是「做不到」：

1. **完整 IP 池**：只能反复采样逼近，永远可能漏
2. **自动切换**：Verge 没有可编程的重载入口，现在是手改 hosts / Script
3. **探测深度**：只测 TCP 握手，还没测 TLS 和真实 HTTP 请求
4. **根本质量**：机场整体差时只能选相对好的——但「选得准」本身就能省掉大量盲试

## 为什么这么设计

| 设计 | 原因 |
|---|---|
| **纯只读** | 排查阶段改配置会把变量搅乱，越改越难定位 |
| **按网络环境分层** | 不分层的话，家里测出的 alive 会盖掉学校测出的 dead |
| **低频探测** | 高频探测本身会变成「异常流量」，反而更容易被限制 |
| **优先用当前选中节点的端口** | 统计最多的端口不一定是实际在用的，两者可能不同 |

## 排查中踩的坑（附录）

这次排查走了不少弯路，记下来免得再走一遍。

| 坑 | 说明 |
|---|---|
| **误判成「全是学校封的」** | 一开始把连不上都归因于校园网。三点对照后才发现，有些 IP 在哪儿都不通——是机场自己的死 IP |
| **误判成「TUN 环路」** | 路由表显示节点 IP 走 utun，就断定 TUN 吞了流量。实际 mihomo 会把到节点的连接绑到物理网卡，路由表只是表象 |
| **误判成「DNS 污染」** | 系统 DNS 返回一堆不同 IP，以为是投毒。实际是机场配了多条 A 记录做轮询 |
| **忽略端口差异** | 一直测 61750，后来从 Verge 配置读出来，主力节点其实用 28537 |
| **只看单点，没有对照** | 只在学校测，就以为「不通 = 被封」。必须跨网络对照才能定性 |

**结论：同一个 IP，在家通、学校不通 = 网络封的；在家也不通 = 机场死 IP；到哪都通 = 真健康。**
